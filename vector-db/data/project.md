# Архитектура проекта AI-ассистента

Проект состоит из четырёх сервисов Docker Compose:

1. `nginx` — единая точка входа, публикует порт 8080 и проксирует запросы на
   `web`. Для SSE отключает буферизацию.
2. `web` — Node.js-приложение на Fastify со встроенным OpenCode SDK. Отдаёт
   REST API, SSE-стриминг и статический чат-интерфейс.
3. `vector-db` — search-сервис поверх Qdrant. Реализует `GET /healthz` и
   `POST /search`, при старте создаёт коллекцию и загружает документы.
4. `qdrant` — векторная база данных. Хранит embeddings документов и выполняет
   поиск по косинусному расстоянию.

## RAG

RAG (Retrieval-Augmented Generation) — подход, при котором в промпт добавляются
найденные в базе знаний фрагменты. Веб-сервис вызывает `/search` только при
первом сообщении в сессии. Найденные фрагменты добавляются в начало промпта с
пометками источников. Если векторная база недоступна, чат продолжает работать
без контекста, а `/health` сообщает об ошибке зависимости.

Контракт search-сервиса:

```http
POST /search
Content-Type: application/json

{ "query": "что такое Docker", "limit": 5, "collection": "knowledge" }
```

```json
{
  "results": [
    { "text": "фрагмент", "score": 0.87, "metadata": { "source": "docker.md" } }
  ]
}
```

## Проверка готовности

`GET /health` у веб-сервиса — это readiness. Он возвращает `200` только если:

- встроенный OpenCode host создан и отвечает;
- SQLite-база читается;
- подписка на события OpenCode установлена;
- модель по умолчанию доступна (если `REQUIRE_MODEL=true`);
- векторная база отвечает (если `VECTOR_DB_URL` задан).

`GET /live` — liveness: процесс жив. Nginx зависит от `web` по условию
`service_healthy`, а `web` — от `vector-db`, поэтому внешний порт открывается
только после полной готовности цепочки.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build
curl -fsS http://localhost:8080/health
```

Интерфейс доступен по адресу <http://localhost:8080>.
