# Docker: контейнеры и образы

Docker — платформа контейнеризации. Контейнер — это изолированный процесс,
который использует ядро Linux, но имеет собственную файловую систему, сеть и
переменные окружения. Контейнер запускается из образа.

Образ (image) — неизменяемый шаблон: слои файловой системы плюс метаданные
(команда запуска, переменные окружения, точки монтирования, healthcheck).
Образ собирается по `Dockerfile`. Каждая инструкция создаёт слой, а слои
кэшируются, поэтому порядок инструкций влияет на скорость сборки.

Основные инструкции `Dockerfile`:

- `FROM` — базовый образ;
- `WORKDIR` — рабочая директория внутри образа;
- `COPY` — копирование файлов из контекста сборки;
- `RUN` — команда, выполняемая во время сборки;
- `ENV` — переменные окружения;
- `USER` — пользователь, от которого работает контейнер;
- `EXPOSE` — документирует порт, который слушает приложение;
- `HEALTHCHECK` — команда проверки готовности контейнера;
- `CMD` — команда запуска по умолчанию.

Важно: приложение внутри контейнера должно слушать `0.0.0.0`, а не
`127.0.0.1`, иначе опубликованный порт не будет доступен с хоста.

## Образы и контейнеры

`docker build` создаёт образ. `docker run` создаёт контейнер из образа.
`docker ps` показывает запущенные контейнеры, `docker images` — локальные
образы. `docker compose` описывает несколько сервисов в одном YAML-файле и
управляет ими как единым приложением.

## Тома

Данные внутри контейнера исчезают при его удалении. Для сохранения данных
используются тома (volumes). В `compose.yaml` том объявляется в секции
`volumes` и монтируется в контейнер, например база данных SQLite или storage
векторной базы Qdrant.

## Healthcheck и readiness

Healthcheck — это команда, которая периодически проверяет, что контейнер
работоспособен. В Docker Compose можно указать `depends_on` с условием
`condition: service_healthy`, чтобы зависимый сервис стартовал только после
того, как зависимость станет здоровой.

Readiness-проверка (`/health`) отвечает `200` только когда сервис реально
готов принимать запросы: база данных доступна, модель настроена, зависимости
отвечают. Liveness-проверка (`/live`) отвечает `200`, если процесс жив, даже
если он ещё инициализируется.

## Docker Compose

`compose.yaml` описывает сервисы, сети, тома и зависимости. Пример:

```yaml
services:
  web:
    build: ./web
    ports:
      - "8080:8080"
    depends_on:
      db:
        condition: service_healthy
```

По умолчанию Compose создаёт общую сеть, и сервисы обращаются друг к другу по
именам сервисов: `http://vector-db:8080`, `http://qdrant:6333`.
